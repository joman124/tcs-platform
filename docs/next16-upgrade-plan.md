# Plan: upgrade to Next.js 16 (separate piece of work)

Decided 2026-10-05: do this as its own PR, not mixed with feature work. **Done 2026-10-05** (`next` 16.3.8): see "Result" at the end.

## Why

`npm audit --omit=dev` reports a high-severity PostCSS advisory in the copy bundled inside `next` (PostCSS ≤ 8.5.22). Here it only processes our own stylesheet at build time, so the practical exposure is low, but it should not linger.

Checked on npm, 2026-10-05:

| | Version | Bundled PostCSS |
|---|---|---|
| Current | `next` 15.5.27 (the newest 15.x) | 8.4.31 (affected) |
| Target | `next` 16.3.8 (latest) | 8.5.23 (fixed) |

There is no 15.x release with the fix, so the fix means the major upgrade. `next-auth@5.0.0-beta.32` (pinned) declares support for Next 14, 15 and 16. React 19 is already in use. Next 16 needs Node 20.9 or newer.

## What changes in this repo

| Area | Change | Notes |
|---|---|---|
| `middleware.ts` | Rename to `proxy.ts`. Next 16 deprecates `middleware.ts`; the proxy runs on the Node.js runtime and must have a default export or a named `proxy` export. | Ours already uses a default export (the demo-mode bypass wrapping `auth()`), so the content should carry over. Keep the matcher, including the `api/auth` and `api/log-retention` exclusions. |
| Request APIs | `cookies()`, `headers()`, `params`, `searchParams` can no longer be used synchronously. | We do not read any of these synchronously today. Run the codemod anyway and review its diff. |
| `package.json` | `next` to 16.3.x; `engines.node` from `>=20` to `>=20.9`; keep `next-auth` pinned. | Regenerate the lockfile with npm. |
| Build | `next build` uses Turbopack by default. | Confirm the build and the print stylesheet are unchanged (the e2e PDF checks cover the print layout). |
| Lint | `next lint` is removed. | We do not use it. |
| `next.config.mjs` | Security headers stay. | Check the build output for any deprecation warnings. |
| Vercel | Project Node.js version must be 20.9+ (Settings → Build and Deployment). | Read it; change it only if needed, and only with the user's approval. |

Dev-only follow-up in the same PR or right after: `vitest` 2 → 5 (clears the dev-only `vite`/`esbuild`/`@vitest/mocker` advisories). It does not touch the app.

## Steps

1. New branch from `main`. Record the baseline: `npm test`, `npm run typecheck`, `npm run build && npm run e2e`.
2. `npx @next/codemod@latest upgrade latest`, or bump `next` by hand, then `npm install` (lockfile regenerated by npm, never by hand).
3. Rename `middleware.ts` to `proxy.ts` (the codemod may already do it). Update the references in `README.md`, `docs/`, and the comment in `src/data/retention.ts`.
4. Bump `engines.node` to `>=20.9`.
5. Run the full suite. Pay particular attention to the sign-in checks (e2e section 11: redirect to sign-in, guarded log/refresh routes, `/diagnostics`, the log-retention 404) and the print-layout checks.
6. `npm audit --omit=dev`. **Expected:** no PostCSS advisory.
7. Push and open a PR. Confirm the Vercel preview reaches READY and the demo preview works.
8. Before release, sign in once on a deployment with the real settings (or rerun Phase 5 section A from `docs/phase5-checklist.md`). Real Entra sign-in through the proxy is the one thing the demo preview cannot exercise.
9. Merge only with the user's approval (the user approves PRs and releases). Production does not deploy automatically from `main` (`vercel.json`); release deliberately.

## Rollback

Revert the PR. Nothing else (data, settings, SharePoint) is touched by this upgrade.

## Result (2026-10-05)

- `next` 15.5.27 → **16.3.8**; `engines.node` `>=20.9`; `next-auth` stays pinned at `5.0.0-beta.32`. Lockfile regenerated by npm.
- `middleware.ts` → **`proxy.ts`** (default export renamed `proxy`; content unchanged). Comments updated.
- `next build` now runs on Turbopack. It rewrote `tsconfig.json` with Next 16's required settings (`jsx: react-jsx`, `.next/dev/types` include); kept as generated.
- No code used synchronous request APIs, so nothing else changed. No codemod was needed.
- Checks: unit 165/165, typecheck clean, browser 74/74 (including sign-in redirect, guarded APIs, the "not set up" page with no settings, and the US Letter print checks). `npm audit --omit=dev`: **0 vulnerabilities** (the PostCSS advisory is gone).
- Still to do before a release: one real Entra sign-in through the proxy (step 8 above). The demo preview cannot exercise it.
- Follow-up, dev tooling only: `npm audit` still reports the vitest/vite/vite-node/esbuild advisories (they do not ship to Vercel). Fixing them means vitest 5, which no longer uses `vite-node`, the runner of `npm run fee-schedule-diff`; switch that script to another TypeScript runner in the same change.
